# Sakura personal site

One Astro project for Jinzheng Wang's academic homepage (`/`) and the Sakura blog (`/Blog/`), deployed together to GitHub Pages.

## Development

Use Node.js 24 and npm from this repository:

```powershell
npm ci
npm run dev
npm run build
npm run preview
npm test
```

The development server uses port 4321. Visit `http://localhost:4321/` and `http://localhost:4321/Blog/`. Build output is `dist/`. `npm test` runs unit tests, builds the site, checks public output, then runs desktop/mobile Playwright tests. Install the browser once with `npx playwright install --only-shell chromium`.

Astro is pinned to 7.3.6: the 7.3.0 content/image build referenced an unexported internal logger; the patch release fixes that path. Markdown uses unified and remark-math to parse TeX. KaTeX renders HTML and accessible MathML at build time. Display equations retain their original TeX for the copy button.

Sharp and KaTeX use patched release lines. The lockfile records the reviewed versions, and dependency auditing is part of the cutover checks.

## Content and assets

- `_posts/`: public blog Markdown written directly or generated by the optional publisher. Both directory-style `permalink` values and legacy `.html` values are accepted.
- `content/pages/`: editable standalone blog pages. Archive and the blog index are Astro pages.
- `public/Blog/assets/`: existing blog image and vendor URLs. `public/assets/` contains homepage assets and the shared self-hosted Chinese font.
- `src/pages/` defines the public routes. The homepage and blog each own their layout, components, styles, and browser code under `src/features/`.
- `src/features/homepage/profile.ts` contains profile and education details. The homepage body and its sections start in `src/pages/index.astro`.
- `src/features/blog/content.ts` reads Astro collections and resolves content routes. `endpoints.ts` generates the Atom feed, search index, and both sitemaps. Blog Markdown rendering and historical heading anchors also live in this feature.
- `src/shared/` provides the HTML document, theme controls, and dates. The initial theme script loads in the head on both sections. Astro bundles the feature scripts and ordered stylesheets.
- `src/config/` holds the site origin, date time zone, URL conventions, and content directories shared by Astro and the publishing scripts.

The homepage has a fixed header with About, Education, and Publications navigation. On narrow screens, the profile stacks above the content and the navigation collapses into a menu.

The blog ships a static reading column, a native collapsible table of contents, and a local search page. Inter and Noto Serif SC are served locally for body text and headings respectively. The body stack includes native Chinese sans-serif fonts. Blog visitors start in dark mode and can switch themes. Cover metadata supplies images for link previews.

Published dates use Asia/Shanghai. Article links use `/Blog/YYYY-MM-DD/slug/`. Archive, About, and Search also have directory-style addresses. The GitHub Pages build emits static redirects for the previous `.html` addresses. Browser redirects preserve query strings and heading fragments. Atom entries keep their existing IDs and link to the directory-style addresses. The migration baseline checks retained heading IDs, images, mathematical expressions and tables. One old Jekyll parsing artifact—a norm expression rendered as an extra table—is intentionally rendered as math.

## Write a post by hand

Create `_posts/2026-11-18-my-post.md` with Markdown and YAML front matter.

```markdown
---
title: "My post"
date: "2026-11-18"
slug: my-post
categories: [学习]
summary: "A short description for the blog and search."
---

Write the article here.
```

`date` and `slug` define the permalink. This example builds to `/Blog/2026-11-18/my-post/`. An explicit `permalink` can retain the publication date and slug from an existing address. The default category is `随笔`. `summary` and cover metadata are optional. Add images under `public/Blog/assets/images/` and link to them using standard Markdown with a `/Blog/assets/images/…` URL.

Untagged code fences receive basic highlighting for numbers, operators, literals, and comments. Use a language tag for language-specific highlighting or `text` for plain preformatted text.

Run `npm run build` and commit the Markdown file and any images. The article goes through the same rendering, archive, search, feed, and sitemap pipeline as other posts.

## Optional Obsidian publisher

The publisher has its own package, lockfile, and tests under [`tools/obsidian-publisher/`](tools/obsidian-publisher/README.md). It produces public Markdown and images that Astro can build directly. Vault snapshots under `obsidian/Published/` belong to the publisher. The site build and deployment install and run only the root package.

## Repository history and production cutover

This repository starts from one reviewed snapshot of the unified Astro project. The previous homepage repository is retained as `sakur7a.github.io-legacy-20261008`, including its template and migration history. The original `sakur7a/Blog` repository also retains its files and history. Source acknowledgements and licenses are preserved separately from Git history in `THIRD_PARTY_NOTICES.md` and `licenses/`.

The canonical repository is `sakur7a/sakur7a.github.io`. Its `main` workflow validates, builds and deploys both `/` and `/Blog/`; pull requests only validate. Deployment is restricted to this canonical repository, so temporary validation repositories and renamed backups do not deploy. The old Blog Pages publishing and deployment workflow are disabled after the unified deployment passes its production checks.

Production cutover completed on 2026-10-08. The unified homepage and blog retain their original URLs. The retained Blog and legacy homepage repositories have Pages and their deployment workflows disabled. Desktop/mobile production checks verified all 12 article addresses, images, RSS, search, formulas and shared theme state. Republishing preserves the currently published cover and crop, including when a Vault original contains older cover metadata; explicitly selecting a new cover or crop replaces it.

The desktop publisher targets `D:\MyHomepage\sakur7a.github.io`. The original plugin is backed up at `D:/ProjectBackups/20261008-obsidian-unified/`. Repository bundles, reviewed snapshots, and cutover records are retained under `D:/ProjectBackups/20261008-clean-site/`.

For rollback, rename the unified repository aside, return the legacy homepage repository to `sakur7a.github.io`, restore its Pages workflow, and re-enable the old Blog Pages/workflow. Restore the previous vault plugin and its `D:\MyBlog` setting. Both retained repositories and the Vault remain available; the archived mobile publisher and private site are not part of this migration.
